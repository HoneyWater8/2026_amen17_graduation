## 2단계 · 전개 방식 탐색 (4종)

같은 7개 섹션·같은 데이터를, 서로 다른 **진행 메커니즘**으로 구현했습니다. 스킨은 각 방식에 가장 어울리는 것을 임시로 입혔습니다.

| 시안 | 방식 | 임시 스킨 | 판단 |
|---|---|---|---|
| **N1 · Story** | 상단 7칸 진행바 + 좌우 탭 + 자동 진행(일시정지 가능) | 시상식 | ❌ 반려 — 자동 진행이 강요처럼 느껴짐. 인스타 스토리 문법이 초대장에 안 맞음 |
| **N2 · Hub** | 중앙 회전 엠블럼 + 하단 6개 메뉴 → 패널 슬라이드업 | 애니버서리 | ○ 원신 레퍼런스에 가장 근접. 다만 게임 UI 색이 강함 |
| **N3 · Envelope** | 봉투 탭 → 플랩 젖힘 → 카드 상승 → 본문 전개 | 졸업장 | ✅ **채택** |
| **N4 · Book** | 8페이지 플립 + 좌우 스와이프 + 페이지 목록 | 졸업장·앨범 | ○ 안정적이나 인상이 약함 |

> 📸 `screenshots/explorations/n1-story.png`, `n2-hub.png`, `n4-book.png`

**채택 이유 (N3)**
- **초대장이라는 물건의 은유가 그대로 인터랙션이 됨.** 봉투를 열어 편지를 꺼낸다 — 설명이 필요 없음
- 열기 전/후가 명확히 나뉘어 **한 번의 임팩트**를 만듦. 이후에는 조용한 세로 스크롤로 정보 전달에 집중
- 졸업장 스킨과 궁합이 가장 좋음 (왁스 씰이 봉투 위에 자연스럽게 놓임)
- 스크롤은 모두가 아는 조작 — 학습 비용 0

## 3단계 · 애니메이션 강화 탐색 (3종)

"원신 이벤트 페이지 같은 느낌"이 아직 부족하다는 피드백을 받고, **모션 자체가 주인공인** 방향을 별도로 탐색했습니다.

| 시안 | 방식 | 결과 |
|---|---|---|
| **N5 · Motion** | 스크롤이 곧 타임라인. 장면별 pin + 진행도(0→1)가 모션을 구동. 엠블럼 조립, 숫자 카운트업, 카드 흩어짐→정렬, 선 그리기 | 스크럽 감각은 좋았으나 정보 전달 밀도가 떨어짐 |
| **N6 · Character** | 캐릭터가 좌하단 고정, 배경이 흘러가는 횡스크롤. 오프닝에 "아멘" 만세 동작, 진행 중 TV·표지판 형태로 콘텐츠 등장 | 아이디어는 좋았으나 제작 규모가 커지고 톤이 가벼워짐 |
| **N7 · Mono** | 흑백 서사시. 사용자 제공 손 스냅 8프레임 시퀀스로 오프닝, 이후 라인아트 + 텍스트로 진행. 인터랙션 최소 | 완성도는 높았으나 졸업 축하의 따뜻함과 거리가 있음 |

> 📸 `screenshots/explorations/n5-motion.png`, `n6-character.png`, `n7-mono.png`

**결론**: 세 방향 모두 **연출이 정보를 밀어냈습니다.** 이 페이지의 1차 목적은 영상 시청과 정보 확인이고, 모션은 그것을 돕는 역할이어야 함. N3(봉투)로 회귀하되, **오프닝 연출에만 힘을 집중**하는 것으로 정리.

> 이 단계는 버려진 시간이 아니라, "어디까지 가면 과한가"의 경계를 확인한 과정이었습니다.

## 4단계 · 최종안 다듬기

N3 채택 후 실제 데이터와 함께 완성도를 올린 과정입니다.

### 4-1. 구조 정리

| 변경 | 이유 |
|---|---|
| 「일시·장소」 섹션 삭제 | 표지 하단 한 줄로 충분. 별도 섹션은 과잉 |
| 「17기의 순간들」을 「함께 걸어온 길」에 흡수 | 사진과 시기가 따로 노는 것보다, **각 시기에 그때 사진**이 붙는 편이 서사가 살아남 |
| 영상 선택 탭 제거 | 통합본 1개로 확정됨 |
| 「함께하지 못한 지체」 블록 제거 | 명단 섹션이 무거워짐 |
| 각 섹션 `min-height: 100%` | 스크롤 리듬 통일 |

### 4-2. 봉투 연출 디버깅

프로토타입에서 실제로 겪은 문제들:

1. **버튼이 안 눌림** — 안쪽 카드가 봉투보다 커서 버튼 위를 덮고 있었음 → 카드 비율·`z-index` 조정
2. **열린 뒤 플랩이 사라짐** — `backface-visibility: hidden` 때문에 172도 회전 시 뒷면이 되어 소멸 → 제거하고 `preserve-3d` + 안쪽 면용 그라데이션 추가
3. **카드가 봉투 아래로 삐져나옴** — `aspect-ratio`를 줘도 flex 자식의 min-content 높이가 더 커서 늘어남 → `overflow: hidden` + 콘텐츠 축소
4. **모바일 상단에 배경 띠** — `100vh`가 주소창을 포함 → `100dvh` + body 배경을 첫 섹션 색과 일치
5. **버튼 → 전면 터치로 변경** — 봉투 어디를 눌러도 열리는 편이 자연스러움. 안내 문구에 호흡 애니메이션 추가

### 4-3. 타이포그래피 결정

**요구**: 통일 폰트는 나눔명조, 포인트는 "해리포터 느낌의 필기체, 단 가독성 유지"

1차로 라틴 전용 후보 5종(Cinzel Decorative / IM Fell English SC / Grenze Gotisch / Marcellus SC / Cormorant Garamond Italic)을 실제 문구로 조판해 비교.

한글 지원 요구가 추가되어 한글 후보 6종(송명 / 함렛 / 기랑해랑 / 나눔손글씨 붓 / 고운바탕 / 가석)도 조판.

> 📸 `screenshots/explorations/font-candidates.png`

**최종 결정**: 한글 장식체는 모두 기각. **포인트 폰트를 영문·숫자에만 적용**하고 한글은 나눔명조로 통일.
- 본문: **Nanum Myeongjo** (400/700/800)
- 포인트: **Cinzel Decorative** — `AMEN 17TH`, 섹션 영문 라벨, 사진 번호

**주의점 발견**: Cinzel Decorative에 한글 글리프가 없어, 한글이 섞인 문자열(`하나로교회`, `2025 · 봄`, 푸터)에 적용하니 한 줄 안에서 서체가 갈라졌습니다. → 해당 요소들을 모두 나눔명조로 회수.

### 4-4. 컬러 조정

- **어두운 톤 전면 제거** — 초기에 있던 다크 섹션을 걷어내고 종이 톤으로 통일
- **포인트 컬러를 붉은색(`#8C2B22`)으로** — 왁스 씰과 톤을 맞춤. 구분선 다이아몬드, 영문 라벨, 타임라인 마커, 사진 번호에 적용
- **텍스트용 금색 분리** — `#A8862C`는 종이 위에서 대비 3.21:1로 소형 텍스트에 부적합. `#6F5719`(`goldTx`)를 신설해 텍스트에만 사용하고, 원래 금색은 선·테두리 전용으로 남김

### 4-5. 사진 캐러셀

시기별 사진을 3장 → 5장으로 늘리고 세 가지 조작을 모두 지원:

| 조작 | 구현 |
|---|---|
| 터치 스와이프 | 네이티브 스크롤 (`touch-action: pan-x pan-y`) |
| 마우스 드래그 | pointer 이벤트로 `scrollLeft` 조작, `pointerType === 'touch'`는 제외 |
| Shift + 휠 | `wheel` 리스너, 양 끝 도달 시 페이지 스크롤로 양보 |

**버그 2건**:
- 드래그 종료 시 `scrollSnapType = ''`로 초기화했더니, 인라인 스타일로만 지정된 값이라 fallback CSS가 없어 스냅이 영구히 꺼짐 → 원래 값 `'x mandatory'`로 명시 복원
- `touch-action: pan-y`가 브라우저의 가로 터치 스크롤을 차단 → `pan-x pan-y`로 수정

### 4-6. 퍼블리시 대응

첫 배포 시도에서 번들 27MB (제한 16MB) 초과.

| 원인 | 조치 |
|---|---|
| Pretendard 정적 CSS (전 웨이트 × 전 서브셋) | 제거 → 나눔명조로 통일 |
| React 개발 빌드 (~1.2MB) | 프로덕션 빌드로 교체 |
| Babel standalone (~2.9MB) | JSX 사전 컴파일 → `.compiled.js` 직접 로드 |
| 왁스 씰 PNG 670×559 / 222KB | 360×300 / 73KB로 축소 |
| JSX 문자열로만 참조된 이미지를 번들러가 못 찾음 | `<meta name="ext-resource-dependency">` 등록 + `window.__resources` 참조 |

## 회고

**잘한 것**
- 자료가 없는 상태에서 placeholder로 **구조를 먼저 확정**한 것. 실제 데이터가 들어올 때 `grad-data.js` 하나만 바꾸면 되는 구조가 됨
- 스킨과 전개 방식을 **분리해서 탐색**한 것. 섞어서 봤다면 무엇이 좋고 나쁜지 판단하기 어려웠을 것
- 말로 설명하기 어려운 판단(폰트, 전개 방식)은 **실제로 만들어서 비교**한 것

**아쉬운 것**
- 3단계 애니메이션 탐색에 들인 시간. 다만 "과한 지점"을 확인한 소득은 있었음
- 폰트를 처음에 라틴 전용으로만 준비해 한 번 더 돌아간 것. 한글 지원 여부를 먼저 확인했어야 함
- 퍼블리시 용량 제약을 늦게 인지. 웹폰트를 고를 때부터 고려했다면 되돌아가지 않았을 것
