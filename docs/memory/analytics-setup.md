참고 레포에서 **페이지뷰·UV를 아예 수집하지 못한 것**이 아쉬웠던 지점이라, 이번에는 행사 9일 전(2026-09-11)에 미리 붙였습니다.

| | Vercel Web Analytics | Google Analytics 4 |
|---|---|---|
| 맡는 것 | 방문자 · 페이지뷰 · 유입 경로 · 기기 | 봉투 열기 · 섹션 도달 · 영상 재생 · 공유 · 사진 확대 |
| 상태 | 2026-09-11 활성화 완료 | 측정 ID `G-P7PXPF9CWM`, Vercel 환경 변수 `VITE_GA_ID` 등록 완료 |
| 쿠키 | 없음 | 사용 |
| 보존 | **1개월** (Hobby) | 14개월 |

**Why 둘 다인가:** Hobby 플랜은 **커스텀 이벤트를 지원하지 않고 리포팅 윈도우가 1개월**입니다(이벤트 한도 5만/월은 이 규모에 충분). "봉투를 열었나 / 어디까지 봤나"는 Vercel로 볼 수 없어 GA4가 그 구멍을 메웁니다. Pro 트라이얼로도 되지만 종료 후 과금되고 플랜을 올렸다 내려야 합니다.

## ⏰ 2026년 10월 중순 — 데이터가 사라지기 전에

**Hobby는 Vercel 데이터를 1개월만 보존합니다.** 행사(2026-09-20) 후 한 달이 지나면 볼 수 없습니다. 참고 레포처럼 통계를 문서로 정리할 계획이라면 **10월 중순 전에 대시보드를 캡처**해야 합니다. GA4는 14개월이라 여유가 있습니다.

## 확인·디버깅

- **`?ga_debug=1`** 로 접속하면 `config`에 `debug_mode`가 실려 GA4 **DebugView**에 실시간으로 찍힙니다. 재배포 없이 켜고 끌 수 있습니다.
- 전송 자체는 개발자 도구 Network에서 `collect?v=2` 요청으로 확인합니다. **`204 No Content` + `tid`가 측정 ID와 일치**하면 브라우저 쪽은 정상입니다.
- 스트림 상세의 "데이터 수집이 활성화되어 있지 않습니다" 배너는 **48시간 기준**이라, 붙인 직후 떠 있어도 이상이 아닙니다. 신규 속성은 첫 데이터가 보고서에 반영되기까지 지연이 있습니다.

## How to apply

- 이벤트를 추가할 때는 `FE/src/utils/analytics.ts`의 `track(name, params, once)`를 씁니다. `once=true`면 같은 키로 한 번만 보냅니다(스크롤 왕복 대비).
- **`VITE_GA_ID`가 없으면 GA 코드가 번들에서 통째로 사라집니다** — Vite가 죽은 코드로 판단해 제거합니다. 의도된 동작이며, ID를 넣고 빌드하면 살아납니다.
- 측정 ID는 스크립트에 노출되는 공개 값이라 Vercel에 `--type config`로 등록했습니다 ([[kakao-app-setup]]의 JS키와 같은 성격).
