**커밋·푸시는 사용자가 하라고 할 때만 진행합니다.** 작업이 끝났다고 알아서 커밋하지 않습니다. (2026-09-07 지시)

**Why:** 이 레포는 `main` push가 곧 **공개 배포**입니다 ([[vercel-deploy-setup]]). Git 연동이 걸려 있어 push하면 자동으로 프로덕션이 갱신되고, 그 URL은 교인 전체에게 공유될 페이지입니다. 즉 push는 "저장"이 아니라 "발행"이라, 무엇이 언제 나가는지는 사용자가 정할 일입니다.

**How to apply:**

- 작업을 마치면 변경 사항을 요약해 보고하고 **커밋하지 않은 상태로 둡니다.**
- 빌드·린트·검증은 지시 없이 해도 됩니다. 되돌릴 수 없는 것은 커밋과 push뿐입니다.
- **"커밋 진행해" 같은 커밋 지시는 푸시까지 포함합니다.** 커밋만 하고 멈추지 말 것 (2026-09-07 확인).
  `main` push는 곧 자동 배포이므로, 커밋 지시는 곧 배포 지시이기도 합니다.
- 그 외에는 "푸시해줘" / "배포해줘" 같은 명시적 지시가 있을 때만 실행합니다.
- **배포는 `main` 커밋·푸시 후 자동 배포로 진행합니다.** 사용자가 2026-09-22 직접 배포 명령은 필요 없다고 재확인했습니다. `vercel deploy`·`vercel redeploy` 등으로 별도 배포하지 않습니다.
- 커밋할 때는 [[github-identity]]의 개인 identity를 씁니다.

## 현재 실행 환경의 승인 제약 (2026-09-16)

위 사용자 선호와 별개로, 자동 승인 검토는 **"커밋 진행해"만 명시된 요청의 `git push origin main`을 거절했다.** 푸시가 공개 배포를 일으키며 메모리 지침만으로 승인 범위를 확대할 수 없다는 이유였다.

이 환경에서는 커밋 요청 시 로컬 커밋까지 완료하고, **푸시·공개 배포는 사용자가 명시적으로 승인한 뒤** 진행한다. 동일한 거절을 다른 명령이나 도구로 우회하지 않는다. 이는 사용자 선호가 바뀐 것이 아니라 실제 실행 환경의 제한을 기록한 것이다.
