**원본 자산은 저장소에 넣지 않습니다.** 사진은 리사이즈본만 커밋합니다. 영상은 원본과 재생용 변환본 모두 로컬에 보관하고, 변환 스크립트·관리 문서만 커밋합니다.

| 자산 | 원본 | 저장소 |
|---|---|---|
| 여정 사진 | 첫 수령분 원본은 **2026-09-11 삭제** (Google Drive에 있을 것으로 추정). 2026-09-16 추가 수령한 식사 모임 원본은 `assets/photo-originals/fellowship/`에 보관 | `FE/public/journey/<slug>/{thumb,full}/NN.jpg` (리사이즈본만 커밋) |
| 영상 | **2026-09-16 정리: `assets/video-originals/`에 원본 10개 보존**. 간증 4개 + 감사 6개 | `FE/public/video/`에는 경량·고화질 재생본만 생성. 원본·변환 중간 파일·재생본 모두 git 제외 |

**Why:** 원본은 장당 수 MB입니다(하나로가족한마당 19장은 전부 7728×5152). 저장소에 넣으면 클론이 무거워지고, 어차피 화면에는 훨씬 작은 크기로만 쓰입니다. 재생성 스크립트가 있으면 원본을 커밋할 이유가 없습니다.

**How to apply:**

- 새 사진을 받으면 `scripts/resize-photos.py`의 `FOLDERS`에 `<한글 폴더명>: <영문 slug>`를 등록하고 실행합니다. `pip install pillow` 필요.
- 그다음 `FE/src/data/graduation.ts`에서 **장수만** 고칩니다 — 경로는 `photosOf(slug, count, label)`이 규칙으로 만듭니다. 파일명을 나열하지 마세요.
- **첫 수령분 59장은 로컬에 원본이 없습니다.** 해당 사진을 다른 크기로 다시 뽑거나 크롭을 바꿔야 하면 발주 측(또는 Google Drive)에서 원본을 다시 받아야 합니다. 첫 수령분은 thumb 320w · full 1280w 두 벌뿐입니다.
- 추가 수령한 `KakaoTalk_20260916_115318409_02.jpg`는 `assets/photo-originals/fellowship/`에 원본 그대로 보관하며 Git에서 제외합니다. 화면에서는 `fellowship/{thumb,full}/18.jpg`를 사용합니다.
- 사진을 일부만 추가할 때는 기존 번호 다음에 이어 붙입니다. `resize-photos.py`는 매번 `01.jpg`부터 생성하므로 추가 수령분만 넣어 기존 출력 폴더에 실행하면 기존 사진을 덮어쓸 수 있습니다. 이번 추가분은 기존과 같은 규격(thumb 320w·품질 78 / full 1280w·품질 82)으로 `18.jpg` 두 벌만 생성했습니다.
- **제자 수업 사진은 더 이상 수급 대기 대상이 아닙니다.** 2026-09-16 발주 측의 최종 삭제 요청을 사용자가 전달했습니다. 성구암송은 앞선 대화에서 나온 대안일 뿐 확정 요청이 아니므로, 별도 지시 없이 대체 항목을 만들거나 사진을 기다리며 복원하지 않습니다.

## 로컬 영상 · 보존과 후속 작업

2026-09-16 사용자가 논의한 폴더 구조와 경량·고화질 변환을 진행하라고 요청했다. 기존 `FE/public/video/`의 원본을 `assets/video-originals/`로 옮기고 정본 초원명을 반영했다. 이동 전후 SHA-256을 비교했으며, 수령 파일명·새 경로·해시는 원본 폴더의 `inventory.json`에 남아 있다.

- 간증 수령분은 초원 **02·08·09·10**이다. 원본 파일의 청년 팀 번호를 화면 번호로 사용하지 않는다.
- 감사 영상은 초원 카드에 배정하지 않는다. 사용자가 **하나로 합쳐 「함께 걸어온 길」의 졸업식 영상으로 사용**한다고 명시했다.
- 감사 영상의 합치는 순서는 별도 지정을 받지 못해 안내한 기본안을 사용했다. 이후 사용자 요청으로 마지막 원본 파일명을 `청년-06.mp4`로 정정하여 현재 순서는 **장년 1→3→4→5, 청년 2→6**이다. 영상 내용과 연결 순서는 그대로이며 모든 구간을 유지한다.
- `청년_감사영상_5.mp4`는 수령 당시 이름이며 현재 보존 파일명은 `gratitude/청년-06.mp4`다. `inventory.json`의 `received_name`은 출처 기록이므로 바꾸지 않고 `archived_path`에 현재 이름을 기록한다. 변환 캐시와 합본 구간 목록도 새 이름으로 갱신했다.
- 영상 원본은 향후 재편집에 필요하므로 보존한다. `assets/video-work/`는 변환 로그·중간 파일·검증 결과이며 원본과 구분한다.
- 상세 파일 대응·규격·재생성 명령은 [영상 자산 관리](../video-assets.md), 재생성 도구는 `scripts/prepare-videos.py`를 기준으로 확인한다.

**파일 준비와 화면 연결은 별개다.** 사용자는 작은 화면에서는 경량본, 전체화면에서는 원본 해상도의 영상을 원한다. 이번 작업은 영상 파일 정리·변환까지이며, 플레이어의 소스 전환과 공개 URL 연결은 아직 구현하지 않았다.

재생용 파일은 총 **10개**다. 간증 4편과 감사 통합본 1편에 각각 `preview.mp4`와 `full.mp4`가 있다. 새 환경에서 저장소를 클론해도 영상 파일은 내려오지 않으므로, 현재 원본 보관 폴더를 따로 옮기거나 수령처에서 다시 확보해야 한다.

간증 섹션 참고 이미지 원본은 `C:\Users\kjyjy\Downloads\KakaoTalk_20260915_094358116.png`입니다. 사용자 제공 이미지이며 저장소에는 포함하지 않았습니다. 확정 초원명과 배치 순서는 `FE/src/data/graduation.ts`를 기준으로 확인합니다.

## 아이콘 · 썸네일

`FE/public/icons/`의 파일들도 원본에서 가공한 것이며 원본은 커밋하지 않습니다. 생성 스크립트를 따로 두지 않았으므로 방법만 적어둡니다 (Pillow).

| 파일 | 만든 방법 |
|---|---|
| `thumbnail.png` 1200×630 | 시안 스크린샷에서 배경색과 다른 픽셀의 bbox를 재어 콘텐츠만 크롭 → 상하 여백 14%를 두고 중앙 배치 → 남는 자리는 원본 배경색으로 채움 |
| `favicon-32/180.png` | `seal/wax-seal.png`의 알파 bbox를 크롭해 정사각 캔버스에 여백 8%로 중앙 배치 (투명 유지) |
| `apple-touch-icon.png` | 위와 같되 배경을 `EV.paper`로 채움 — iOS는 투명 영역을 검게 채운다 |
