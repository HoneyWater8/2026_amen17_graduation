**원본 자산은 저장소에 넣지 않습니다.** 사진은 리사이즈본만 커밋합니다. 영상은 원본과 재생용 변환본 모두 로컬에 보관하고, 변환 스크립트·관리 문서만 커밋합니다. 공개 재생용 경량본은 Vercel Blob에 따로 업로드합니다.

| 자산 | 원본 | 저장소 |
|---|---|---|
| 여정 사진 | 첫 수령분 원본은 **2026-09-11 삭제** (Google Drive에 있을 것으로 추정). 추가 수령 원본은 `assets/photo-originals/fellowship/`과 `graduation/`에 보관 | `FE/public/journey/<slug>/{thumb,full}/NN.jpg` (리사이즈본만 커밋) |
| 영상 | **2026-09-26 기준: `assets/video-originals/`에 원본 21개 보존**. 새 간증 10개 + 이전 간증 4개 + 감사 7개 | `FE/public/video/`에 새 간증 10개·감사 합본의 경량/고화질 재생본 22개 보관. 원본·변환 중간 파일·재생본 모두 git 제외 |

**Why:** 원본은 장당 수 MB입니다(하나로가족한마당 19장은 전부 7728×5152). 저장소에 넣으면 클론이 무거워지고, 어차피 화면에는 훨씬 작은 크기로만 쓰입니다. 재생성 스크립트가 있으면 원본을 커밋할 이유가 없습니다.

**How to apply:**

- 새 사진을 받으면 `scripts/resize-photos.py --source <원본 파일 또는 폴더> --slug <시기> --start <첫 번호>`로 변환합니다. `pip install pillow` 필요. 폴더를 지정할 때는 새 사진만 있는 폴더를 사용합니다.
- 그다음 `FE/src/data/graduation.ts`에서 **장수만** 고칩니다 — 경로는 `photosOf(slug, count, label)`이 규칙으로 만듭니다. 파일명을 나열하지 마세요.
- **첫 수령분 59장은 로컬에 원본이 없습니다.** 해당 사진을 다른 크기로 다시 뽑거나 크롭을 바꿔야 하면 발주 측(또는 Google Drive)에서 원본을 다시 받아야 합니다. 첫 수령분은 thumb 320w · full 1280w 두 벌뿐입니다.
- 추가 수령한 `KakaoTalk_20260916_115318409_02.jpg`는 `assets/photo-originals/fellowship/`에 원본 그대로 보관하며 Git에서 제외합니다. 화면에서는 `fellowship/{thumb,full}/18.jpg`를 사용합니다.
- 사진을 일부만 추가할 때는 기존 번호 다음에 이어 붙입니다. **2026-09-22부터 변환 도구가 기존 출력 덮어쓰기를 거부**하므로 `--start`로 새 번호를 지정합니다. 규격은 thumb 320w·품질 78 / full 1280w·품질 82입니다.
- 졸업 예배는 **2026-09-20 진행 완료**이며 사진을 더 받을 예정입니다. 단체 사진 원본은 `assets/photo-originals/graduation/01.jpg`로 보관했고, 다음 사진은 `02.jpg`부터 추가합니다. 수령 당시 파일명 `감사영상 추가된거.jpg`는 내용과 달랐으므로 원본 폴더의 `inventory.json`에 출처로만 남겼습니다.
- **제자 수업 사진은 더 이상 수급 대기 대상이 아닙니다.** 2026-09-16 발주 측의 최종 삭제 요청을 사용자가 전달했습니다. 성구암송은 앞선 대화에서 나온 대안일 뿐 확정 요청이 아니므로, 별도 지시 없이 대체 항목을 만들거나 사진을 기다리며 복원하지 않습니다.

## 로컬 영상 · 보존과 후속 작업

2026-09-16 사용자가 논의한 폴더 구조와 경량·고화질 변환을 진행하라고 요청했다. 기존 `FE/public/video/`의 원본을 `assets/video-originals/`로 옮기고 정본 초원명을 반영했다. 이동 전후 SHA-256을 비교했으며, 수령 파일명·새 경로·해시는 원본 폴더의 `inventory.json`에 남아 있다.

- **2026-09-25 초원 01~10 간증 영상 전부 수령 완료.** `수헌이전달간증`의 파일 10개를 정본 초원명에 맞춰 `testimony/NN_초원명.mp4`로 정리했다. 사용자가 이번 요청에서 감사영상이라고 표현했지만, 폴더·파일명과 영상 내용은 초원별 간증이므로 기존 `gratitude/` 합본에 넣지 않는다. 원본 파일의 청년 팀 번호를 화면 번호로 사용하지 않는다.
- 새 수령분 중 02·08·09·10도 기존 원본과 길이·해시가 다르다. 이전 원본 4개는 `archive/2026-09-25/testimony/`에 보존했다. 새 원본 10개와 이전 4개, 감사 7개 모두 이동 후 크기·SHA-256을 검증했으며 출처는 `inventory.json`에 기록했다.
- 감사 영상은 초원 카드에 배정하지 않는다. 사용자가 **하나로 합쳐 「함께 걸어온 길」의 졸업식 영상으로 사용**한다고 명시했다.
- **2026-09-22 사용자 요청 반영: 감사 영상은 장년·청년 구분 없이 번호 오름차순으로 연결하며, 파일명은 `NN-그룹.mp4`로 통일한다.** 순서는 **01-장년 → 02-청년 → 03-장년 → 04-장년 → 05-장년 → 06-청년 → 07-장년**이다. 변환 도구가 앞 번호를 숫자로 정렬하므로 새 영상을 목록 어디에 넣어도 번호순으로 합쳐진다.
- 2026-09-22 받은 `졸업 단체 사진.mp4`는 실제로 약 1분 48초의 감사 영상이다. 사용자가 장년 7번으로 지정했고 최종 보존 이름은 **`gratitude/07-장년.mp4`**다. 장년·청년 뒤에 번호를 두던 형식과 임시 이름 `추가-20260922-01.mp4`는 사용하지 않는다.
- `청년_감사영상_5.mp4`는 수령 당시 이름이며 사용자 정정 번호는 6번, 현재 보존 파일명은 `gratitude/06-청년.mp4`다. `inventory.json`의 `received_name`은 출처 기록이므로 바꾸지 않고 `archived_path`에 현재 이름을 기록한다. 변환 캐시와 합본 구간 목록도 새 이름으로 갱신했다.
- 영상 원본은 향후 재편집에 필요하므로 보존한다. `assets/video-work/`는 변환 로그·중간 파일·검증 결과이며 원본과 구분한다.
- Windows에서 영상을 다시 만들 때는 로컬 미리보기 서버를 먼저 종료한다. 2026-09-22 Vite가 기존 MP4를 잡고 있어 검증 완료 파일의 교체가 막혔으며, 서버 종료 후 변환 결과를 그대로 배치해 해결했다.
- 상세 파일 대응·규격·재생성 명령은 [영상 자산 관리](../video-assets.md), 재생성 도구는 `scripts/prepare-videos.py`를 기준으로 확인한다.

**2026-09-26 사용자 요청으로 새 간증 10편을 변환하고 경량본을 Vercel Blob에 공개 업로드했다.** Production/Preview의 `VITE_TESTIMONY_1_VIDEO_URL`~`VITE_TESTIMONY_10_VIDEO_URL`을 새 주소로 등록·교체했고, `VITE_GRADUATION_VIDEO_URL`은 기존 감사 합본 주소를 유지한다. 로컬에서도 10개 초원 모두 `/video/testimony/NN/preview.mp4`를 기본 경로로 사용한다. 전체화면 고화질 전환과 `full.mp4` 공개 업로드는 후속 작업이다.

재생용 파일은 총 **22개**다. 간증 10편과 감사 통합본 1편에 각각 `preview.mp4`와 `full.mp4`가 있다. 새 환경에서 저장소를 클론해도 영상 파일은 내려오지 않으므로, 현재 원본 보관 폴더를 따로 옮기거나 수령처에서 다시 확보해야 한다.

**영상 교체는 로컬 변환 → Blob 업로드 → 공개 URL 환경 변수 변경 → `main` 커밋·푸시를 통한 자동 배포 순서다.** 직접 배포 명령은 사용하지 않는다. Git 푸시만으로 로컬 영상 파일이 전송되지는 않는다. 현재 Blob 저장소는 `amen17-graduation-videos` (`store_zw4d65fKlIme6aVE`, 서울 `icn1`, Public)이며 현재 연결된 경량본 11개는 총 211.29 MiB다. 이전 간증 Blob 4개도 복구용으로 보존한다. 파일명에는 SHA-256 앞 12자리를 붙여 교체 시 새 경로를 사용한다. 주소와 절차는 [영상 자산 관리](../video-assets.md#공개-배포-vercel-blob)를 따른다.

간증 섹션 참고 이미지 원본은 `C:\Users\kjyjy\Downloads\KakaoTalk_20260915_094358116.png`입니다. 사용자 제공 이미지이며 저장소에는 포함하지 않았습니다. 확정 초원명과 배치 순서는 `FE/src/data/graduation.ts`를 기준으로 확인합니다.

## 아이콘 · 썸네일

`FE/public/icons/`의 파일들도 원본에서 가공한 것이며 원본은 커밋하지 않습니다. 생성 스크립트를 따로 두지 않았으므로 방법만 적어둡니다 (Pillow).

| 파일 | 만든 방법 |
|---|---|
| `thumbnail.png` 1200×630 | 시안 스크린샷에서 배경색과 다른 픽셀의 bbox를 재어 콘텐츠만 크롭 → 상하 여백 14%를 두고 중앙 배치 → 남는 자리는 원본 배경색으로 채움 |
| `favicon-32/180.png` | `seal/wax-seal.png`의 알파 bbox를 크롭해 정사각 캔버스에 여백 8%로 중앙 배치 (투명 유지) |
| `apple-touch-icon.png` | 위와 같되 배경을 `EV.paper`로 채움 — iOS는 투명 영역을 검게 채운다 |
