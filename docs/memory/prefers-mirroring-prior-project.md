구조·스택을 정할 때 **이전 프로젝트를 그대로 답습하는 쪽**을 선택합니다. 이번 프로젝트에서 두 번 확인되었습니다.

1. "`C:\dev\2026_hanaro_family_festival` 의 레포를 참고하여 폴더 구조를 잡는것이 좋을거야"
2. 핸드오프 문서가 Next.js도 제안했지만 — "스택은 참고 레포와 동일하도록 진행하면 될것 같아"

**Why:** 같은 팀·같은 사람이 연달아 만드는 소규모 프로젝트라, 구조가 같으면 다음 프로젝트에서도 바로 읽힙니다. 최신 스택으로 갈아타는 이득보다 일관성의 이득이 큽니다.

**How to apply:**

- 구조·설정·네이밍에 선택지가 생기면 먼저 [[reference-repo-hanaro-festival]]에서 같은 상황을 어떻게 처리했는지 찾아보고 그대로 따릅니다.
- 참고 레포에 없는 새 패턴이 필요하면 이유를 밝히고 제안한 뒤 진행합니다.
- 또 하나 확인된 선호: **작업 전 조사를 끝까지 시키고, 계획을 승인한 뒤 실행**하는 순서를 원합니다 ("구조 및 히스토리 같은것들을 모두 정확하게 빠짐없이 조사해야해", "다시한번 확실하게 ... 빠짐없이 파악하고 작업 진행해").
