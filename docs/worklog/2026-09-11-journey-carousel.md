## 판단한 것

**1. 이미지를 두 벌로 나눈 것**

원본은 장당 수 MB — 하나로가족한마당 19장은 전부 **7728×5152**였습니다. 카드가 화면에서 128px인데 7728px 원본을 내려받게 할 수는 없습니다.

| 용도 | 폭 | 근거 |
|---|---|---|
| `thumb` | 320w | 카드 128px × DPR 2배 여유 |
| `full` | 1280w | 루트 460px × DPR 2~3배 |

`full`은 라이트박스를 열 때만 로드되고, `thumb`은 `loading="lazy"`가 걸려 있어 초기 로딩에 다 들어오지 않습니다. EXIF 회전을 `ImageOps.exif_transpose`로 적용했습니다 — 안 하면 스마트폰 촬영본이 눕습니다.

**2. 파일명을 나열하지 않고 규칙으로 생성**

23 + 19 + 17 = 59개 경로를 데이터 파일에 손으로 적으면 사진이 바뀔 때마다 지옥입니다. 리사이즈 단계에서 `01.jpg`, `02.jpg` … 로 다시 매기고, 데이터에는 **장수만** 적습니다.

```ts
photos: photosOf("entrance", 23, "입학식")
```

사진을 더하거나 빼면 숫자 하나만 고치면 됩니다.

**3. 원본 폴더는 커밋하지 않음**

95MB를 저장소에 넣을 이유가 없습니다. `.gitignore`에 `제자17기-*/`를 넣고, 대신 **재생성 스크립트를 커밋**했습니다. 원본이 있으면 누구든 같은 결과를 다시 만들 수 있습니다.

**4. 무한 캐러셀 — 참고 레포 Program 방식**

기존 `PhotoRail`은 네이티브 `overflow-x` + `scroll-snap`이라 끝이 있습니다. 참고 레포 `Program.tsx`의 rAF + `translate3d` 방식으로 갈아탔습니다.

핵심은 참고 레포가 **주석으로 남겨둔 버그 대응**입니다.

> 한 사이클 너비 = N × 카드 stride. `scrollWidth/2`를 쓰면 좌우 padding이 끼어들어 매 사이클마다 `(padding - gap/2)`px씩 어긋남 → 끊김 발생.

그래서 `cycle = length × CARD_STRIDE`로 계산하고, 트랙에 좌우 padding을 주지 않았습니다. 같은 함정을 다시 밟지 않도록 주석을 옮겨 적었습니다.

배열을 두 벌 이어 붙이고(`[...shuffled, ...shuffled]`) offset을 `[-cycle, 0)`으로 wrap하면 이음매가 보이지 않습니다.

**5. 드래그 관성**

손을 뗄 때의 속도를 `inertiaRef`에 담고 `exp(-dt/250)`으로 감쇠시켜 자동 흐름에 합류시킵니다. 참고 레포와 같은 방식입니다. 6px 이상 끌었으면 뒤따르는 클릭을 무시해 — 드래그 끝에 라이트박스가 열리는 사고를 막습니다.

**6. `touch-action: pan-y`**

이전 `PhotoRail`은 네이티브 가로 스크롤을 살리려고 `pan-x pan-y`였습니다. 지금은 가로 이동을 JS가 처리하므로 **`pan-y`가 맞습니다** — 브라우저에는 세로만 넘기고 가로는 트랙이 가져갑니다. `pan-x`를 남겨두면 브라우저의 가로 제스처와 JS 드래그가 서로 싸웁니다.

README 구현 노트 5번("`pan-y`만 주면 네이티브 가로 스크롤이 죽는다")은 **네이티브 스크롤을 쓰던 시절의 규칙**이라 지금 구조에는 해당하지 않습니다. 노트를 갱신했습니다.

**7. 셔플은 `useState` lazy initializer로**

처음에 `useMemo`로 짰다가 `react-hooks/purity` 에러를 만났습니다. `useMemo`는 순수해야 하는데 `Math.random()`이 들어갔기 때문입니다. 규칙을 끄는 대신 `useState(() => shuffle(items))`로 바꿨습니다 — 마운트 시 1회만 실행되고, 재계산으로 순서가 도중에 뒤바뀔 위험도 없습니다.

**8. 라이트박스 — `fixed`여야 한다**

처음에 `position: absolute; inset: 0`으로 짰다가 화면이 이상하게 나왔습니다. 조상인 `Section`이 `position: relative`라, 라이트박스가 **화면이 아니라 Journey 섹션 전체 높이**를 덮은 탓입니다. Journey는 5개 시기가 쌓인 매우 긴 섹션이라 결과가 엉뚱했습니다.

`position: fixed`로 바꾸되, 앱이 460px 폭 안에 갇혀 있으므로 `left: 50%` + `maxWidth: LAYOUT.maxWidth` + `translateX(-50%)`로 앱 폭에 맞췄습니다. 그냥 `inset: 0`으로 두면 데스크톱에서 460px 밖 여백까지 덮습니다.

**9. 모달 크기를 사진 비율과 무관하게 고정**

처음에는 래퍼를 `inline-flex`로 두어 사진 크기에 딱 맞췄는데, 사진마다 세로가 달라 넘길 때마다 틀이 출렁였습니다. 4:3 고정 패널 안에서 `object-fit: contain`으로 보여주도록 바꾸니 좌우로 넘겨도 틀이 흔들리지 않습니다.

배경도 `.88`로 거의 덮던 것을 `.42` + `backdrop-filter: blur(7px)`로 낮췄습니다. 본문이 비쳐 보이면서 시선은 모달로 모입니다.

**10. 이동 수단 네 가지**

요청은 "크게 보기"였지만, 하나 크게 본 사람은 다음도 보고 싶어집니다. 매번 닫고 여는 것은 번거롭습니다. 좌우 스와이프(터치·마우스 드래그, 끄는 동안 모달이 따라 움직임) · 가로 휠(쿨다운 320ms) · 화살표 버튼(모달 위에 얹음) · 키보드를 넣었고, `N / M` 표시와 함께 끝에서 순환합니다.
