# 2026-09-16 · 영상 원본 정리와 경량·고화질 변환

> 원본 10개를 보존용 폴더로 옮기고, 간증 4편과 감사 통합본에 각각 preview/full 재생 파일을 준비했다.

- 이동 전에 원래 이름·목적지·크기·SHA-256을 `assets/video-originals/inventory.json`에 기록하고, 이동 후 해시를 다시 비교했다.
- 간증 02·08·09·10의 `preview.mp4`(960×540)와 `full.mp4`(1280×720)를 생성했다. 고화질본은 영상·음성을 재압축하지 않고 MP4 재생 정보만 앞쪽으로 옮겼다.
- 감사 원본 6개를 전체 길이로 합쳐 `graduation/full.mp4`(2560×1440)와 `preview.mp4`(960×540)를 생성했다.
- 원본과 변환 작업 디렉터리를 Git에서 제외했다. `public`에는 재생 파일만 남겼다.
- 재생성 도구 `scripts/prepare-videos.py`, 자산 관리 문서 `docs/video-assets.md`를 추가하고 README·요구사항·메모리를 갱신했다.

## 판단한 것

- 원본의 청년 팀 번호와 화면 초원 번호는 다르다. 이름을 기준으로 Onlyhim→02, 더드림 가조→08, 어순종팀→09, 부어부어→10으로 연결했다. 미수령 01·03·04·05·06·07에는 빈 파일을 만들지 않았다.
- 감사 영상 합치는 순서를 비동기로 문의하고 독립적인 원본 정리·간증 변환부터 진행했다. 별도 지정이 없어 안내했던 기본안인 장년 1→3→4→5, 청년 2→5를 사용했다. 발언을 임의로 자르거나 배경음·전환 효과를 추가하지 않았다.
- 감사 원본 중 2336×1080 영상이 있어, 가로 크기를 줄이지 않고 담는 16:9 규격인 2560×1440을 통합 고화질본에 사용했다. 작은 원본은 확대되지만 새 디테일이 생기는 것은 아니다. 비율이 다른 영상은 여백을 두어 전체 화면 내용을 보존했다.
- 첫 감사 영상은 회전 -90°와 HLG/BT.2020 메타데이터를 갖고 있었다. 자동 회전과 HDR→SDR 톤 매핑을 적용해 합본을 SDR BT.709로 통일했다.
- 감사 합본의 프레임률·음성을 30fps, AAC 48kHz 스테레오로 맞췄다. 각 구간 끝의 1프레임 미만 길이 차이는 마지막 화면·무음으로 보충했다.
- 변환 중간 파일은 `assets/video-work/`에 쓰고 검증 후에만 최종 경로로 옮긴다. 원본 해시·인자가 같은 결과는 재사용하므로 이후 수령분을 추가하기 쉽다.
- 이번 지시는 영상 파일 정리·변환이다. 플레이어 소스 연결과 전체화면 화질 전환, 영상 호스팅 업로드는 별도 후속 작업으로 남겼다.

## 확인한 것

- 원본 10개의 이동 전후 SHA-256과 파일 크기가 일치했다.
- 간증 고화질본 4개의 영상·음성 패킷 해시가 각각 원본과 일치했다.
- 재생 파일은 H.264/AAC, yuv420p, 지정 해상도·길이, MP4 faststart 구조를 확인하고 전체 구간을 오류 없이 디코딩했다.
- 감사 합본의 여섯 구간에서 프레임을 추출해 순서, 회전, 색상, 화면 비율을 확인했다.
- 간증 변환을 다시 실행해 완료한 8개 파일이 재인코딩 없이 재사용되는 것을 확인했다.
- 변환 스크립트의 초원명 10개와 순서가 화면 데이터와 일치했다.
- `npm run build`, `npm run lint`, `git diff --check` 통과.
- 최종 재생용 MP4 10개와 원본 10개의 목록·크기를 대조했다. 각 영상의 preview/full 길이 차이는 1프레임 미만이며, 간증 4편은 정확히 같았다.
- 감사 통합본 길이는 644.867초, 경량본 54.66 MiB, 고화질본 497.25 MiB다. 간증 경량본 4개 합계는 34.33 MiB로 고화질본보다 약 65% 작다.
