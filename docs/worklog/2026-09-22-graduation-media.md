## 한 일

- 졸업 단체 사진을 `journey/graduation/{thumb,full}/01.jpg`로 추가했다. 전체 여정 사진은 61장이며 사진을 더 받을 예정이다.

- 사진 변환 도구에 `--source`, `--slug`, `--start`를 추가하고 기존 출력 덮어쓰기를 막았다. 다음 졸업 예배 사진은 `02.jpg`부터 이어 붙일 수 있다.

## 판단한 것

- 수령 파일 이름이 실제 내용과 반대였다. `감사영상 추가된거.jpg`가 단체 사진이고 `졸업 단체 사진.mp4`가 감사 영상인 것을 이미지·영상 프레임으로 확인했다.
- 사진 원본은 `assets/photo-originals/graduation/01.jpg`, 감사 영상 원본은 `assets/video-originals/gratitude/추가-20260922-01.mp4`로 옮겼다. 각 보관 폴더의 `inventory.json`에 수령 이름·해시를 남겼다.
- 추가 영상의 팀 번호는 전달되지 않아 임의로 청년·장년 번호를 배정하지 않았다. 합치는 위치는 별도 응답이 없어 미리 안내한 기본안인 맨 뒤를 사용한다. 기존 내용은 자르지 않는다.
- 사진은 기존의 320w·1280w 규격, 합본은 기존의 540p 경량본·1440p 고화질본 규격을 유지한다. 원본은 보존하고 화면용 사진만 Git에 포함한다.

## 확인한 것

- 모바일 320·390·460px에서 사진·영상 동시 표시, 사진 확대·닫기, 가로 넘침 없음을 확인했다.
- 사진 0·1·2·3장의 캐러셀 동작을 브라우저에서 확인했다. 두세 장은 화면을 채워 움직이고, 한 장은 복제 없이 고정된다. 런타임 예외 없음.
- 원본 영상 11개와 새 사진의 SHA-256을 확인했다. 사진 변환을 같은 번호로 다시 실행하면 기존 파일을 그대로 두고 거부한다.
- 감사 합본 두 벌의 H.264/AAC·faststart·전체 디코딩을 검증했다. 길이는 약 752.767초로 같고, 변환 도구 재실행 시 두 파일 모두 재인코딩 없이 재사용한다.
- 빌드된 화면에서 합본의 650초 지점으로 이동해 새 수령분이 실제 재생되는 것을 확인했다. 경량본은 960×540이며 재생 오류·런타임 예외가 없었다.
- `npm run build`, `npm run lint`, `git diff --check`를 통과했다. 빌드에 복사된 새 사진·합본도 원래 재생용 파일과 일치한다.

## 남긴 것
