# 2026-09-22 · 감사 영상 번호순 연결과 원본 파일명 통일

> 감사 영상의 재생 순서를 장년·청년 구분 없이 번호순으로 바꾸고, 원본도 번호가 앞에 오는 이름으로 정리한다.

## 한 일

- 이전 합본의 1→3→4→5→2→6→7 순서를 1→2→3→4→5→6→7로 변경했다.
- 사용자 제안에 따라 `assets/video-originals/gratitude/`의 원본 이름을 `01-장년.mp4`, `02-청년.mp4`, `03-장년.mp4`, `04-장년.mp4`, `05-장년.mp4`, `06-청년.mp4`, `07-장년.mp4`로 통일했다.
- `GRATITUDE`는 파일명 앞 번호를 숫자로 정렬한다. 목록을 추가한 위치와 장년·청년 구분에 영향을 받지 않는다.
- 경량본·고화질본을 같은 순서로 다시 생성하고 원본 목록, 변환 캐시, 구간 목록과 관리 문서에 새 이름을 반영했다.

## 판단한 것

- 처음에는 순서 지정이 없어 장년·청년을 묶었지만, 사용자가 번호순 재생을 요청했다. 임의로 그룹별로 다시 묶지 않는다.
- 번호를 앞에 두면 일반적인 파일명 정렬과 재생 순서가 일치한다. 파일명의 번호는 두 자리로 유지하고 변환 도구에서는 문자열 대신 숫자로 비교한다.
- 수령 파일명은 출처이므로 `inventory.json`의 `received_name`을 유지하고 `archived_path`만 갱신한다. 사용자 정정 번호인 청년 6번·장년 7번도 유지한다.
- 파일명 정리 제안은 변환 도중에 전달받았다. 진행 중인 변환을 마친 뒤 파일을 옮기고 내용 해시·변환 인자 일치를 확인해 캐시를 갱신했다.

## 확인한 것

- 원본 7개는 이름 변경 전후 SHA-256이 일치한다. 수령 당시 이름은 원본 목록에 그대로 보존했다.
- 새 순서의 구간 시작은 0 / 15.7 / 54.4 / 64.2 / 76.8 / 533.3 / 644.867초다. 각 구간 시작 2초 뒤의 프레임을 해당 원본과 대조해 경량·고화질 두 벌 모두 일치하는 내용을 확인했다.
- 두 합본의 전체 디코딩·H.264/AAC·해상도·faststart·길이 검증을 통과했다. 길이는 약 752.767초다.
- 변환 도구를 새 파일명으로 다시 실행해 두 파일 모두 캐시에서 재사용되는 것을 확인했다.
- `npm run build`와 `git diff --check`를 통과했다.

## 남긴 것

- 새 감사 영상은 `NN-그룹.mp4` 형식으로 보관하고 `GRATITUDE` 목록에 추가한다. 번호가 재생 순서를 결정한다.
- 영상 공개 URL 업로드와 전체화면 화질 전환은 별도 후속 작업이다.
