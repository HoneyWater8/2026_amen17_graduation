# 2026-09-22 · Vercel 영상 공개 배포와 단일 재생

> 프로덕션에서 영상이 모두 준비 안내로 보이던 문제를 Vercel Blob 업로드와 환경 변수 연결로 해결하고, 한 번에 하나만 재생하도록 반영했다.

- 기존 Hobby 팀에 Public Blob 저장소 `amen17-graduation-videos` (`store_zw4d65fKlIme6aVE`, 서울 `icn1`)를 만들고 기존 프로젝트에 연결했다.
- 사용자의 공개 업로드 승인 후 간증 02·08·09·10과 감사 합본의 경량본 5개, 총 104,466,463 B를 업로드했다.
- `VITE_TESTIMONY_{2,8,9,10}_VIDEO_URL`과 `VITE_GRADUATION_VIDEO_URL`을 Production/Preview에 등록하고 기존 커밋 `1543438`을 재배포했다.

- 변경된 프론트엔드를 CLI로 배포했다. 최종 프로덕션 배포 ID는 `dpl_2z4bzLzGMPuHG26Bsn3cVX4TiafW`, 공개 주소는 기존 https://2026amen17graduation.vercel.app 이다.
- README·환경 변수 예시·요구사항·영상 관리 문서·메모리를 현재 운영 상태로 갱신했다.

## 판단한 것

- 사용자가 지정한 Vercel 안에서 파일을 제공하도록 Blob을 사용했다. 공개 URL 환경 변수는 다음 Git 배포에도 유지되므로 영상 파일을 Git에 추가할 필요가 없다.
- 현재 플레이어가 사용하는 경량본만 올렸다. 원본·고화질본은 로컬에 보존하며 전체화면 화질 전환 구현과 함께 고화질 배포를 진행한다.
- Blob 파일명에는 콘텐츠 SHA-256 앞 12자리를 넣었다. 영상 교체 시 새 경로를 사용하고 새 배포 확인 전 기존 파일을 삭제하지 않는다.
- 첫 공개 업로드가 자동 승인 검토에서 거절되어 대상 5편과 Public Blob 공개 범위를 안내했다. 사용자가 다시 공개 업로드를 명시 승인한 뒤 진행했다.
- CLI 59.25.0의 연결 과정에서 `.env.local`에 OIDC 토큰만 있고 저장소 ID가 없어 `BLOB_STORE_ID`를 추가했다. 자동 추가된 `.gitignore` 끝의 중복 `.env*`는 제거해 `!.env.example` 예외를 보존했다. 인증 토큰은 기록하거나 커밋하지 않았다.
- 단일 재생은 공통 플레이어의 재생 이벤트에서 다른 영상에 `pause()`만 호출한다. 별도 상태 저장 없이 브라우저가 재생 위치를 유지한다.
- 코드 변경 배포는 추적 중인 FE 파일과 프로젝트 연결 정보만 임시 디렉터리에 복사해 진행했다. 업로드 루트 아래 `FE/`를 유지해 기존 Root Directory와 맞췄고 로컬 MP4·인증 파일은 제외했다. 이번 요청에는 새 커밋·푸시를 추가로 수행하지 않았다.

## 확인한 것

- 공개 영상 5개 모두 HEAD 200, `video/mp4`, 로컬과 같은 크기. 첫·끝 1,024바이트 Range 요청은 206이며 로컬 내용과 일치했다.
- 실제 프로덕션 모바일 390px에서 영상 5개의 960×540 해상도, 길이, 실제 재생, 75% 지점 탐색을 확인했다. 미수령 6개 초원의 준비 안내도 유지됐다.
- 단일 재생 변경 후 `npm run build`, `npm run lint` 통과. Vercel 프로덕션 빌드도 성공했다.
- 로컬 빌드와 최종 실배포에서 `02 → 08 → 감사 합본 → 09 → 10 → 02` 순서로 실제 재생했다. 각 단계의 재생 중 영상은 하나이며 이전 영상의 시간이 멈추고, 02 재개 시 이전 위치부터 이어졌다. 런타임 예외 없음.
- 첫 원격 단일 재생 검증은 300ms 고정 대기 때문에 초기 버퍼링 중 실패했다. 실제 재생 시간이 증가할 때까지 기다리도록 검증을 수정한 뒤 통과했으며 앱 코드는 변경하지 않았다.
- 영상·인증 파일은 여전히 Git 제외 대상이다.
