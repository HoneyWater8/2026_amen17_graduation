# 2026-09-26 · 새 간증 영상 10편 변환과 공개 배포

> 초원별 새 수령본 10편의 경량·고화질 재생본을 만들고, 공개 경량본 URL을 전체 초원에 연결한다.

## 한 일

- `python scripts/prepare-videos.py --section testimony`로 새 간증 10편의 `preview.mp4`와 `full.mp4`, 총 20개를 생성했다. 감사 합본은 기존 결과를 유지했다.
- 경량본은 960×540 H.264/AAC, 원본 프레임률 유지, 총 153,084,474 B(145.99 MiB)다. 원본 해상도를 유지한 고화질본보다 약 94.6% 작다.
- 기존 Public Blob 저장소 `amen17-graduation-videos`에 10편을 `video/testimony/NN/preview-<SHA256 앞 12자리>.mp4`로 업로드했다.
- `VITE_TESTIMONY_1_VIDEO_URL`~`VITE_TESTIMONY_10_VIDEO_URL`을 Production/Preview에 등록·교체했다. 감사 합본의 URL은 유지한다.
- 로컬에서도 10개 초원 모두 `/video/testimony/NN/preview.mp4`를 사용하도록 기본 경로를 연결했다. 이름·배치 순서는 사용자 정본을 유지했다.
- 영상 관리 문서와 `docs/memory/`에 원본 21개, 재생용 22개, 현재 공개 연결 11개 상태와 후속 작업을 기록했다.

## 판단한 것

- 사용자의 요청은 새 영상의 변환·배포다. 기존 공개 배포 방식대로 경량본을 Blob에 올리고, 앱은 `main` 커밋·푸시의 Git 자동 배포로 반영한다. 직접 Vercel 배포 명령을 사용하지 않는다.
- 기존 4개 초원도 새 수령본의 내용·길이가 달라 모두 교체한다. 해시가 포함된 새 URL로 캐시를 구분하고, 이전 Blob 4개는 복구용으로 보존한다.
- 고화질본은 1080p 8개와 720p 2개(04·10)이며 원본 스트림을 재압축하지 않았다. 총 약 2.63 GiB로 로컬에 보관한다. 고화질본 공개와 전체화면 화질 전환은 기존 후속 작업으로 유지한다.
- Blob 업로드 시 기존 인증이 만료되어 접근이 거절됐다. CLI 60.0.1의 `vercel env pull`로 갱신한 뒤 정상 업로드했다. 토큰은 Git 제외 파일에만 두고 앱에는 공개 영상 URL만 전달한다.

## 확인한 것

- 변환 결과 20개 모두 H.264/AAC·해상도·길이·faststart 구조 및 끝까지 디코딩 검증 통과.
- 보관 원본 21개의 크기와 SHA-256이 `inventory.json`과 일치. 원본과 감사 합본은 변경하지 않았다.
- 공개 영상 11개 모두 `HEAD 200`, `video/mp4`, 정확한 파일 크기, 앞·뒤 1,024바이트의 `Range 206` 및 로컬 데이터 일치 확인.
- `npm run build`, `npm run lint` 통과.
- 로컬 Chrome에서 간증 10편과 감사 합본의 메타데이터·실제 재생·75% 구간 이동을 확인했다. 다른 영상 재생 시 이전 영상이 멈추고 위치가 유지되며, 첫 영상으로 돌아가 이어 재생하는 12회 전환 검증 통과.
- 화면 폭 320·390·460px에서 정본 이름, 2열 × 5행, 가로 넘침 없음 확인. 런타임 예외 없음.
