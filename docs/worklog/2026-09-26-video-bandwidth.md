# 2026-09-26 · 영상 전송량의 코드 최적화

> 재생 버튼을 누르기 전에는 MP4를 요청하지 않고, 다른 영상 선택·탭 전환·페이지 이탈 시 다운로드를 중단한다. 전체화면 고화질과 이어보기는 유지한다.

## 한 일

- 공통 `VideoSlot`에서 초기 `src`를 제거하고 별도 WebP 포스터와 재생 버튼을 표시했다. 버튼 클릭 안에서 영상 주소를 연결하고 `play()`를 호출해 사용자 입력에 따른 재생을 유지한다. 재생 이후에는 기존 네이티브 컨트롤을 사용한다.
- `connectVideoQuality`에서 재생 시작·다운로드 해제·화질 전환을 함께 관리한다. 다른 영상이 시작되거나 문서가 숨겨지거나 `pagehide`가 발생하면 재생 위치·속도·음량·음소거를 기억한 뒤 `src`를 제거하고 `load()`로 요청을 중단한다. 복귀만으로 재요청하지 않으며 클릭해야 이어 본다. 끝까지 본 영상은 처음부터 시작한다.
- 해제할 때 고화질 로딩 타이머와 예약된 자동 재개도 취소한다. 늦게 전달된 play/pause/error가 현재 재생을 중단하거나 해제한 영상을 다시 로드하지 않도록 처리했다.
- 전체화면 전환 후 복원이 끝나기 직전에 사용자가 재생하면, 지연된 `play` 이벤트 때문에 다시 멈추던 경합을 보완했다. 이벤트뿐 아니라 현재 `paused` 상태도 확인한다.
- `scripts/prepare-videos.py --section posters`를 추가했다. 기존 경량본의 1초 지점에서 640×360, 품질 75의 WebP 11장을 만들었다. `FE/public/video-posters/`에 두어 Git 배포에 포함한다. 합계 163,112 B. 재실행 시 입력·출력 해시를 확인해 재사용하며 수동 교체한 출력은 덮어쓰지 않는다.
- 코드·환경 변수 안내·영상 관리 문서·메모리를 갱신했다. MP4 변환·추가 업로드·원격 환경 변수·요금제·호스팅은 변경하지 않았다.

## 판단한 것

- 기존 구현은 봉투 뒤에 모든 영상을 마운트하고 `src`와 `preload="metadata"`를 즉시 설정했다. 봉투를 열지 않고 재생하지 않아도 영상 11개의 요청이 발생했다. `preload="none"`만으로는 브라우저에 대한 힌트이므로, 확실히 막기 위해 클릭 전 주소 자체를 연결하지 않는다.
- 기존 첫 프레임 표시를 유지하려면 별도 이미지가 필요하다. 영상에서 추출한 작은 WebP를 사이트에 배포하면 MP4 메타데이터를 내려받을 이유가 없다. 기존 초원 카드·정본 이름·배치는 유지한다.
- `pause()`만으로는 후속 버퍼링을 막지 못한다. 다른 영상을 고르거나 페이지를 떠날 때 주소를 해제한다. 네이티브 컨트롤의 짧은 일시정지는 연결을 유지해 곧바로 다시 볼 수 있도록 한다.
- 영상 해상도·비트레이트와 전체화면 고화질 요구는 유지한다. 시청한 영상의 전송 비용은 계속 발생하며, 소스 전환이나 다운로드 해제 후 다시 보기에는 재요청이 생길 수 있다. 전체 전송량이 일정 비율로 감소하거나 1년간 무료 한도를 지킨다는 의미는 아니다.
- 사용자는 Pro 결제를 장애 복구의 임시 조치로 설명했고 링크를 최소 1년 유지해야 한다고 요청했다. 우선 코드만 최적화하며 호스팅 이전·결제 취소는 확정하지 않는다.

## 확인한 것

### 재생 전 네트워크

새 Chrome 프로필에서 390×844 화면, 봉투를 열지 않은 상태로 8초 동안 관찰했다. 분석용 네트워크 요청은 차단하고 영상·포스터의 응답 바이트를 집계했다.

| 조건 | MP4 요청 | MP4 응답 바이트 | 별도 영상 포스터 |
|---|---:|---:|---:|
| 변경 전 프로덕션 (`5854cbe`) | 11건 | 3,400,677 B | 없음 |
| 변경 후 로컬 production 빌드 | 0건 | 0 B | 11장, 163,112 B |

초기 영상 관련 응답 데이터가 이 측정에서는 약 95.2% 줄었다. 봉투를 열고 아래로 스크롤해도 클릭 전 MP4 요청은 0건이다. 사이트 전체 리소스의 감소율이나 실제 Vercel 청구 절감률을 뜻하지 않는다.

### 재생·중단·화질

- 클릭한 경량본만 요청하고, 다른 영상 선택 시 이전 요소의 `src`가 사라지는 것을 확인했다. 이전 영상을 다시 클릭하면 약 31초의 위치와 1.25배속·음량 0.35·음소거가 복원됐다. 연결된 영상은 한 번에 하나였다.
- Chrome에서 실제로 다른 탭을 활성화해 `visibilityState=hidden`과 소스 해제를 확인했다. 돌아온 것만으로 요청하지 않고 재생 버튼으로 이어 봤다.
- 간증 10편·감사 합본 1편 모두 실제 전체화면에서 540p → 각 고화질 해상도 → 540p 전환을 확인했다. 일시정지·재생, 위치·속도·음량·음소거를 보존했다. 감사 합본은 2560×1440, 간증 04·10은 1280×720, 나머지는 1920×1080이다.
- 고화질 요청을 의도적으로 차단했을 때 같은 25초 위치의 경량본으로 복귀했다. 페이지 런타임 예외는 없었다.
- 320px·390px 화면의 포스터·재생 버튼·초원명을 확인했고 가로 넘침이 없었다.
- `npm test`: 24개 통과. 초기 무요청, 중단·재개, 탭 숨김·페이지 이탈, 화질 전환·오류·시간 초과, 재생 권한 거절, 지연된 이벤트 경합을 포함한다.
- `npm run build`, `npm run lint` 통과. 썸네일 최초 생성 시 11장 모두 WebP·640×360 확인, 두 번째 실행은 11장 모두 `SKIP`으로 재사용했다.

로컬 검증 기록은 Git 제외 경로 `assets/video-work/initial-media-network.json`(변경 전), `video-bandwidth-browser.json`(변경 후), `report-posters.json`에 보관한다. 브라우저 재생 검증은 로컬 MP4를 사용해 Blob의 추가 전송을 발생시키지 않았다.

## 남긴 것

- 작업 완료 시점에는 커밋·푸시·배포하지 않았다. 사용자 요청으로 `main`에 푸시하면 기존 자동 배포가 반영한다. 직접 배포 명령은 사용하지 않는다.
- iPhone Safari·카카오 인앱 브라우저 실기기는 확인하지 못했다. Safari 전체화면 이벤트 분기는 자동 테스트로 확인했다.
- 실제 청구 절감량은 배포 후 트래픽으로 확인해야 한다. 1년 운영을 위한 영상 호스팅 선택과 결제 취소 시점은 후속 판단 사항이다.
