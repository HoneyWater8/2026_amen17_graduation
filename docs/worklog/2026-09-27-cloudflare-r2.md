# 2026-09-27 · Cloudflare R2 영상 이전

> 기존 졸업 사이트 주소와 플레이어를 유지하면서 영상 저장·전송을 R2 + Workers로 옮긴다.

## 한 일

- 사용자가 생성한 R2 버킷 `amen17-graduation-videos`(APAC, Standard)에 경량본 11개·고화질본 11개, 총 953,071,937B를 업로드했다. 원본·보존용 full·기존 Blob 파일은 보존했다.
- 공식 Wrangler 로그인으로 계정을 연결했고, 영상 업로드에는 사용자가 Git 제외 파일에 저장한 버킷 범위의 S3 키를 사용했다. API 키 값은 출력하지 않았다.
- `cloudflare/video-worker/`에 공개 읽기 전용 Worker와 HTTP 계약 테스트를 추가했다. 공개 주소는 `https://amen17-graduation-videos.2026-amen17-graduation.workers.dev`다.
- 업로드 목록 생성·동일 파일 재실행 확인·multipart 업로드와 공개 주소 검증 스크립트를 추가했다.
- README·환경 변수 예시·메모리·영상 자산 문서를 R2 구성에 맞춰 갱신했다. 현재 반영 단계는 [운영 문서](../cloudflare-r2.md)에 기록한다.

## 판단한 것

- 사용자가 기존 `2026amen17graduation.vercel.app` 주소 유지를 선택했다. 웹앱은 Vercel에 두고 영상은 브라우저가 Cloudflare에서 직접 받는다. Vercel 프록시를 거치지 않는다.
- 별도 도메인을 구매하지 않고 `workers.dev`를 사용한다. R2의 개발용 공개 주소는 끄고 Worker의 R2 바인딩으로 제공한다. 버킷 CORS 설정 대신 Worker 응답에서 기존 사이트 Origin을 허용한다.
- 감사 영상 HD는 368,369,681B로 Wrangler의 300MiB 업로드 제한을 넘는다. 파일을 다시 압축하지 않고 AWS CLI의 multipart 업로드를 사용했다.
- 공개 주소는 내용 해시를 포함해 장기 브라우저 캐시가 이전 영상을 잘못 재사용하지 않게 한다. 메타데이터는 같은 Worker 인스턴스에서 최대 5분 재사용하고 영상 본문은 저장하지 않는다. 본문은 스트림과 Range로 전달한다.
- 1년 유지 요구는 영상 자동 삭제 기한이 아니다. 버킷의 기본 7일 규칙은 미완료 multipart 업로드 정리이며, 완료된 영상을 삭제하는 규칙은 추가하지 않았다.
- R2의 저장·작업 수 무료 한도와 Workers Free의 하루 10만 요청 한도를 별도로 안내한다. 무료·무제한 전송 서비스라고 설명하지 않는다.

## 확인한 것

- Worker HTTP 테스트 21개 통과: 재생·탐색·HEAD·조건부 요청·잘못된 범위·읽기 전용·오류 처리·메타데이터 재사용.
- 프런트엔드 기존 테스트 24개, 빌드·린트 통과.
- 최종 Worker에서 공개 영상 22개 모두 HEAD 200, Range 206, 크기·MIME·CORS·처음/마지막 바이트가 로컬 파일과 일치했다. 결과는 Git 제외 `assets/video-work/r2-deployment.json`에 있다.
- Vercel Production/Preview 각각 22개 공개 URL을 갱신하고 다시 내려받아 모두 일치함을 확인했다. 로컬 빌드는 R2 URL 22개 포함·기존 Blob 호스트 없음으로 확인했다. `r2-vercel-env-verification.json`에 인증 값 없는 결과만 보관하고 env 대조용 임시 파일은 삭제했다.
- 간증 10편 Chrome에서 540p ↔ 원본 해상도를 유지한 HD(720p 또는 1080p) 왕복 확인. 감사 합본은 별도 검사에서 540p ↔ 1440p 확인했다. 재생 전 MP4 0건, 포스터 11개 163,112B와 단일 재생·위치 복원·탭 숨김 중단도 확인했다.
- 첫 전체 검사는 아직 업로드되지 않은 감사 HD에서 경량본으로 복귀했다. 업로드 완료 후 검사 중에도 일시적인 네트워크 지연과 고화질 준비 시간 초과를 관찰해 감사 영상을 따로 재검증했다. 기존 15초 제한·경량본 복귀 정책은 변경하지 않았다.
- Python 기본 User-Agent는 Cloudflare에서 403 오류 코드 1010을 받았다. 검사 도구를 식별하는 `amen17-video-verifier/1.0`으로 명시했으며 Chrome과 해당 식별자의 요청은 정상 처리된다. 검증 스크립트는 일시적 네트워크 오류만 최대 두 번 재시도하고, 403·404·내용 불일치는 실패로 남긴다.

## 남긴 것

- 감사 합본은 검사 환경에서 고화질 전환 성공과 시간 초과 복귀가 모두 관찰됐다. 최종 Worker에서도 지연이 재현됐으며 이를 완전 해결로 기록하지 않는다. 사용자에게 로컬 R2 연결 페이지에서 직접 재생을 확인하도록 요청했다.
- Vercel 앱 반영은 사용자 커밋·푸시 지시 후 main 자동 배포로 진행한다. Cloudflare Worker 배포와 별개이며 `vercel deploy/redeploy`는 실행하지 않는다.
- iPhone·카카오 인앱 실기기 확인, 장기간 사용량 모니터링은 별도다. 네트워크가 느리면 기존 정책에 따라 고화질 대신 경량본으로 복귀할 수 있다.
