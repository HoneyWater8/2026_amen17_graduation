# 2026-09-27 · 화면 밖 모션과 정적 자산 최적화

> 사용자가 전체 최적화 검토 후 범위를 재확인하고 구현을 지시했다. 캐러셀·정적 캐시·부분 폰트·이미지·썸네일 지연 로딩의 다섯 항목을 적용하고 로컬 프로덕션 빌드에서 검증했다. 커밋·푸시와 실배포 반영은 아직 하지 않았다.

## 작업 범위

- `PhotoRail`: 봉투가 열린 뒤 화면에 보이는 레일만 rAF를 실행한다. 드래그·탭 숨김·모션 감소·라이트박스 표시 중에는 프레임 예약을 취소한다. 확대 보기에서는 다른 사진 레일도 중지한다. 재개할 때 시간 기준을 초기화하고 오래된 관성을 버려 위치가 튀지 않게 한다.
- `useInView`: 사진/포스터 준비는 화면 앞뒤 400px에서 한 번, 자동 이동은 실제 화면 안에서 관찰한다. 준비된 이미지는 화면 밖으로 나가도 src를 해제하지 않는다. 기존 사진별 native lazy loading도 유지한다.
- `ScrollHint`: 표시할 때만 무한 CSS 애니메이션을 붙인다. 봉투 연출과 시간 값은 변경하지 않았다.
- `VideoSlot`: 포스터만 지연 연결한다. 영상 컨트롤러·R2 전송·단일 재생·HD 전환 코드는 변경하지 않았다. 클릭한 영상은 아직 포스터가 준비되지 않았더라도 기존 방식으로 즉시 재생할 수 있다.
- `FE/vercel.json`: 해시 JS/CSS·폰트·씰은 1년 immutable, 고정 이름 사진·영상 포스터·아이콘은 1시간 캐시 후 재검증한다. HTML 기본 재검증은 유지한다. 고정 파일을 즉시 교체하려면 새 파일명을 사용한다.
- 기존 서체에서 현재 콘텐츠에 필요한 글자와 ASCII를 남겨 WOFF2 3개를 만든다. 원본 고정 버전·SHA-256을 검사하고 OFL 예약 이름에 따라 내부 이름을 변경했다. 저작권·OFL 원문은 배포 자산에 포함했다.
- `font-text.mjs`는 TypeScript AST의 문자열·JSX 텍스트·템플릿 문자열을 수집한다. `npm run build`에서 새 글자 누락과 WOFF2 해시를 검사한다. 생성은 `scripts/prepare-fonts.py`로 별도 진행하므로 Vercel 빌드에는 Python이나 외부 폰트 다운로드가 필요 없다.
- 여정 사진 61장의 thumb/full 122개를 WebP로 변환하고 새 화면에서 참조한다. 원본이 남은 식사 모임 18번·졸업 예배 1번은 원본에서, 나머지는 기존 리사이즈 JPEG에서 변환했다. 이전 JPEG는 Git 제외 로컬 경로에 복사·해시 확인했다. **기존 탭에서 이전 JS가 지연 로딩할 사진의 404를 막기 위해 공개 JPEG 주소도 호환용으로 유지한다.** 이는 배포 보관 용량을 늘리지만 새 화면에서 JPEG를 추가 다운로드하지는 않는다.
- 씰은 RGBA 픽셀 값이 모두 같은 무손실 WebP로 제공한다. 기존 PNG는 아이콘 재생성용으로 남겼으며 화면에서는 요청하지 않는다. 카카오 OG PNG와 favicon은 유지한다.

## 확인한 것

- `npm --prefix FE run build`, `npm --prefix FE run lint`, `npm --prefix FE test` 통과. 기존 영상 테스트 24개 모두 통과.
- Vercel 공식 스키마 중 사용하는 `headers` 정의로 캐시 설정을 검증했다. 전체 스키마는 무관한 실험 기능에서 draft 형식이 섞여 검사기가 거절하므로 사용 항목만 분리해 검사했다.
- 새 글자를 임시 TS 소스에 추가했을 때 부분 폰트 검사가 실패하고 재생성 명령을 안내하는 것을 확인한 뒤 임시 파일을 제거했다.
- 생성된 폰트의 cmap·모든 포함 글자의 윤곽 좌표·advance width를 원본과 비교해 일치했다. 새 서체를 적용한 뒤에도 390px에서 5개 섹션의 높이 844/874/1091/953/844px가 기존 실배포와 정확히 같았다.
- 입학식·가족한마당·식사 모임·졸업 예배 사진의 중앙 영역을 나란히 비교해 얼굴·단체 사진·작은 글씨의 변화를 확인했다. WebP는 손실 압축이므로 사진 자체가 무손실이라고 설명하지 않는다. 씰은 별도로 전체 RGBA 바이트 일치를 확인했다.
- Chrome에서 실제 포인터 드래그 후 확대가 잘못 열리지 않는지, 이어지는 탭·확대 이미지 로드·다음 사진·닫기·모든 레일 정지/재개를 확인했다.
- 탭 숨김/복귀·모션 감소·맨 아래 이동에서 rAF 중지, 재진입 시 위치 보존, 320/460px 가로 넘침 없음, 하단 푸터, 공유창 표시를 확인했다. 브라우저 예외 0건.
- R2 실제 영상으로 초기 MP4·포스터 요청 0건, 다른 영상 전환·이어보기, 숨긴 탭에서 src 해제, 간증 1번 540p↔1080p 및 감사 합본 540p↔1440p, 재생 위치·속도·음량·음소거 보존, HD 오류 시 경량 복귀를 확인했다. 브라우저 예외 0건.

## 배포와 유지

- 구현 검증 시점의 공개 사이트는 이전 main `a6f458e`였다. 이후 사용자에게 커밋·푸시 지시를 받았으며, main 푸시로 Git 자동 배포를 진행한다. Vercel 직접 배포 명령은 사용하지 않는다.
- 캐시 헤더는 배포 후 실제 응답에서 최종 확인해야 한다. 로컬 preview의 기본 헤더를 Vercel 캐시 정책 검증으로 간주하지 않는다.
- iPhone·카카오 인앱 브라우저 실기기 검증은 별도다. 이번 브라우저 검증은 Windows Chrome이다.
- 원본과 영상 파일은 보존하며 이미 완료한 Vercel Blob 삭제를 다시 실행하지 않았다. R2·Worker 설정과 요금제는 변경하지 않았다.
- 측정 자료는 Git 제외 `assets/video-work/optimization-after.json`, `optimization-ui.json`, `optimized-video-verification.json`, `optimized-images.json`에 있다. 이미지 비교와 화면 캡처도 같은 폴더에 보관한다.
- 재생성·파일 경로·캐시는 README와 자산/배포 메모리에 반영했다.
