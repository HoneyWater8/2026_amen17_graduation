# 2026-09-27 · 영상 버퍼 확보와 R2 직접 전송

> 사용자가 확인한 초기 대기·재생 중 반복 멈춤을 재현하고 플레이어의 버퍼 확보와 영상 전달 방식을 수정했다.

## 한 일

- 선택한 영상과 화질 전환 중 `preload=auto`를 사용한다. 일시정지 복원 뒤에는 metadata로 줄인다. 다른 영상·탭 숨김·페이지 이탈의 src 해제는 유지한다.
- 영상 호스트의 preconnect로 첫 재생의 연결 준비를 앞당긴다. 11개 슬롯의 같은 호스트 힌트는 React가 합친다. 클릭 전 파일 요청은 없다.
- Worker의 영상 본문 중계를 제거하고 GET 전용 R2 서명 URL로 307 연결한다. 고정 공개 주소와 VITE 설정은 유지한다. HEAD는 기존 바인딩으로 처리한다.
- Cloudflare 공식 예제의 `aws4fetch` 1.0.20을 Worker에만 추가했다. Secret은 stdin으로 같은 계정의 Worker Secret에 등록했으며 브라우저·Git·출력에는 넣지 않았다. 발급 URL도 검증 로그에 기록하지 않는다.
- 서명은 한 시간 단위로 동일하게 생성하고 최소 23시간 유효하다. 307 캐시는 5분으로 제한하며 다음 방문에 갱신한다. 1년 유지할 고정 사이트·영상 주소에 만료된 서명을 하드코딩하지 않는다.
- 버킷 CORS는 졸업 사이트 한 곳의 GET/HEAD만 허용했다. Public Development URL은 계속 꺼져 있다.
- Worker 배포 버전: `b38e35ba-5c86-430d-848f-b08c4fcf9e9b`. Vercel 직접 배포는 실행하지 않았다.

## 판단한 것

- 단순히 15초 HD 제한을 늘리지 않았다. 기존 코드가 화질 전환 시 `load()`로 멈춘 뒤 metadata만 받고, 프레임이 도착해야 재생을 재개하는 조합에서 작은 요청과 대기가 반복됐다. 재생에 필요한 버퍼를 확보하도록 수정했다.
- 해상도·비트레이트·영상 파일은 바꾸지 않았다. 일반 540p·전체화면 HD 및 기존 오류 복귀를 유지한다.
- 작은 구간을 Worker에 캐시하는 방식도 시험했지만 캐시 HIT에서도 지연됐고, 전체 검사에서 3번 간증의 HD 전환이 시간 초과로 경량본에 복귀했다. 최종 구현에서는 구간 캐시를 제거했다.
- 같은 1MiB를 비교했을 때 3번 간증은 Worker/LAX 30.453초 대 R2 직접/ICN 0.671초, 감사 합본은 46.398초 대 0.578초였다. 이 관측으로 Worker 중계 경로가 병목이라고 판단해 본문을 직접 전송하도록 바꿨다. 모든 지역이 언제나 ICN을 경유한다고 보장하지 않는다.
- 업로드용 S3 키는 버킷 CORS 조회에 AccessDenied를 받았다. 기존에 연결한 Wrangler 관리 인증으로 빈 CORS 상태를 확인했다. 전체 Origin 허용은 자동 승인 검토가 범위가 넓다고 거절했고, 실제 사이트 Origin 하나로 제한한 설정은 승인·적용됐다. 추가 사용자 승인이 필요한 미해결 작업은 없다.

## 확인한 것

Chrome에서 브라우저 캐시를 끄고 감사 합본을 일반 재생 30초 → 전체화면 30초 → 250초 지점 탐색 후 30초로 비교했다. 각 숫자는 단일 측정이며 통계적 보장이 아니다. 서버 캐시는 측정별 다를 수 있다.

| 측정 | 첫 재생 | HD 전환 | HD 탐색 | 전환·탐색 직후를 제외한 재생 중 멈춤 |
|---|---:|---:|---:|---:|
| 기존 metadata 방식 | 2.1초 | 10.4초 | 11.3초 | HD 전환 뒤 1회, 탐색 뒤 3회 |
| auto만 적용 | 4.4초 | 4.5초 | 1.9초 | 0회 |
| auto + 구간 캐시 | 3.0초 | 5.8초 | 2.6초 | 0회 |
| 최종 auto + 사전 연결 + R2 직접 전송 | 1.5초 | 10.0초 | 2.3초 | 0회 |

- 최종 검사의 일반 재생 시작은 1.46초였다. HD 전환에서 메타데이터가 약 8.9초 뒤 도착한 측정도 있으므로 첫 전환 대기가 완전히 사라졌다고 설명하지 않는다. 직접 전송은 재생 중 충분한 버퍼를 확보했으며, 250초 탐색 후 약 2.35초에 재개했다.
- 처음 클릭 전 MP4 0건·0B, 포스터 11개 163,112B 유지.
- Worker 26개·플레이어 24개 테스트, FE 빌드·린트 통과. SDK와 별개로 SigV4 서명을 재구성해 GET만 허용·대상 경로·유효 기간·새 날짜의 URL 갱신을 확인했다. Secret 누락은 503, 업로드·삭제·다른 경로는 기존처럼 거부된다.
- 공개 영상 22개 모두 HEAD·처음/마지막 Range·크기·MIME·CORS·로컬 바이트 일치와 최종 R2 S3 전송 호스트를 재검증했다.
- 최종 경로에서 간증 10편과 감사 합본 모두 Chrome 540p ↔ 720/1080/1440p 왕복, 단일 재생, 위치·설정 복원, 탭 숨김 중단·자동 재시작 없음, 오류 시 경량본 복귀, 320px 가로 넘침 없음 확인. 브라우저 예외 0건.
- 성능 측정 원본은 Git 제외 `assets/video-work/r2-buffering-{baseline,auto,cached,direct}.json`에 있다. `cached`는 최종 구조가 아니므로 운영 성능으로 인용하지 않는다.
- 사용자가 후속 확인에서 "영상 버퍼링 없이 잘 나오고 있어"라고 확인하고 커밋·푸시를 지시했다.
