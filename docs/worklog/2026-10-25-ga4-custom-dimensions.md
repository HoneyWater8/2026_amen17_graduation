# 2026-10-25 · GA4 맞춤 측정기준 등록과 링크 공개일 반영

> `section` · `video`를 GA4 맞춤 측정기준으로 등록해 이후 방문분부터 섹션별·영상별로 나눠 볼 수 있게 했고, 링크 공개일(9/26)을 README 일별 추이에 반영했다.

## 한 일

| 대상 | 내용 |
|---|---|
| GA4 관리 → 맞춤 정의 | 맞춤 측정기준 2개 등록 (아래 표) |
| `README.md` | 「사용자 집계」의 등록 0개 경고를 등록 완료로 교체. 「운영 통계」 일별 추이에 링크 공개일 추가, 9/20 0건 해석 보강. 측정 한계 문구 정정 |
| `docs/memory/analytics-setup.md` | 맞춤 측정기준 등록 상태 반영 |

| 측정기준 이름 | 범위 | 이벤트 매개변수 | 설명 |
|---|---|---|---|
| `section` | 이벤트 | `section` | section_view 이벤트의 섹션 라벨 (예: 01 Cover) |
| `video` | 이벤트 | `video` | video_play 이벤트의 영상 키 (testimony-1 ~ testimony-10, graduation) |

## 판단한 것

**1. 소급되지 않아도 지금 등록** — 행사 기간 데이터는 영영 나눠 볼 수 없지만, 링크를 최소 1년 유지하므로 이후 방문분이라도 섹션별·영상별로 보는 편이 낫다고 사용자가 결정했다.

**2. 이름은 매개변수 이름 그대로** — 코드(`track('section_view', { section })`)와 README가 `section` · `video`로 부르므로 보고서에서도 같은 이름으로 찾게 했다. 고유 값은 섹션 5개(`01 Cover` ~ `05 Closing`), 영상 11개라 GA4가 경고하는 고유 값 과다에 해당하지 않는다.

**3. `share_copy`의 `ok`는 등록하지 않음** — 기간 전체 1건이고 성공 여부만 담는 값이라 맞춤 측정기준 한도를 쓸 이유가 없다.

**4. 링크 공개일은 "기억"으로 표기** — 사용자가 "아마 9/26에 공개했을 것"이라고 알려 왔다. 공개 시각 기록은 없어 README에 단정하지 않고 기억으로 적었다. 이로써 9/20(예배 당일) 0건은 링크가 아직 공개되지 않았던 것으로 설명된다.

## 확인한 것

| 항목 | 결과 |
|---|---|
| 매개변수 존재 | 등록 패널의 이벤트 매개변수 목록에 `section` · `video`가 이미 떠 있어 목록에서 골랐다(GA4가 수집한 적 있는 매개변수) |
| 저장 결과 | 맞춤 측정기준 목록 「2개 중 1~2번째」, 두 행 모두 범위 이벤트 · 마지막 변경일 2026년 10월 25일 |
| 보고서 반영 | **확인하지 않음.** 등록 후 수집분부터 반영되며 보고서에 나타나기까지 최대 24~48시간 걸린다 |

로그인은 지난번과 같이 별도 프로필 Chrome(`--remote-debugging-port`)에 사용자가 직접 했고, 작업 후 정상 종료하고 프로필을 삭제했다. 첫 번째 창은 로그인 전에 닫혀 한 번 다시 띄웠다.

## 남긴 것

- 섹션별·영상별 수치는 **2026-10-25 이후 방문분만** 볼 수 있다. 행사 기간(9/11 ~ 10/22) 통계와 섞어 비교하지 말 것.
- 내부 트래픽 필터는 이번에도 등록하지 않았다(요청 범위 밖). 방문이 거의 없는 시기라 영향은 작다.
