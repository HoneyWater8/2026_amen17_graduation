## 작성 규칙

**언제** — 의미 있는 작업 단위가 끝날 때. 커밋 단위보다는 크고, 하루 단위보다는 주제 중심입니다. 파일을 하나 고친 정도로는 쓰지 않습니다.

**파일명** — `YYYY-MM-DD-<영문-kebab-slug>.md`. 제목은 파일 안에 한국어로 씁니다. (slug을 ASCII로 두는 건 git·CLI 출력이 깨지지 않게 하기 위해서입니다.)

**형식**

```markdown
# YYYY-MM-DD · <한국어 제목>

> 한 줄 요약

## 한 일
## 판단한 것        ← 선택지가 있었던 지점과 고른 이유. 이 로그의 핵심
## 확인한 것        ← 검증한 방법과 결과. 검증 못 한 것도 명시
## 남긴 것          ← 다음 사람이 알아야 할 미결·주의사항
```

「판단한 것」이 비어 있다면 그 작업은 로그로 남길 필요가 없었던 것입니다.

**갱신** — 파일을 추가하면 위 「목록」에 한 줄 추가합니다. 지난 로그는 고치지 않습니다. 사실이 바뀌면 새 로그에 씁니다.
